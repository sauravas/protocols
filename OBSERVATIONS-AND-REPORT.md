# I2C, SPI and UART Communication using ESP32-S3

Board: **ESP32-S3-DEVKITC-1** | Firmware: **MicroPython v1.28.0** | Simulator: **Wokwi**

Open <https://wokwi.com/projects/new/micropython-esp32-s3>, paste `diagram.json` and
`main.py` from a folder, press the green play button.

---

## Activity 1 - I2C Device Scanner and LCD Display

### Connections (as specified)
| ESP32-S3 GPIO | I2C signal | LCD1602 pin |
|---|---|---|
| GPIO 8  | SDA | SDA |
| GPIO 9  | SCL | SCL |
| 3V3     | -   | VCC |
| GND     | GND | GND |

### Serial output
```
I2C DEVICE SCANNER
Device: FOUND
Address: 0x27
Status: CONNECTED
Devices detected: 1
```
LCD shows: `DEVICE: FOUND` / `ADDR 0x27  CONN`

### Observation table
| Parameter | Observation |
|---|---|
| SDA pin | GPIO 8 - bidirectional open-drain data line; carries address, R/W bit, data and the slave ACK |
| SCL pin | GPIO 9 - clock generated by the ESP32-S3 master at 100 kHz; SDA may only change while SCL is LOW |
| I2C address | 0x27 (decimal 39) |
| Number of devices detected | 1 |
| Communication status | CONNECTED - the slave pulled SDA low to acknowledge |

### Signal flow
`i2c.scan()` sends a START, then every address 0x08-0x77 with the write bit. A device that
pulls SDA LOW on the 9th clock (ACK) is recorded. Only 0x27 answered - the PCF8574 backpack
on the LCD. LCD characters are then sent as 4-bit nibbles packed into bytes written to 0x27
(P0=RS, P2=EN, P3=backlight, P4-P7=D4-D7).

## Activity 2 - SPI Data Transmission and Waveform Analysis

### Connections (as specified)
| ESP32-S3 GPIO | SPI signal | Goes to |
|---|---|---|
| GPIO 12 | SCK  | Logic analyser D0 |
| GPIO 11 | MOSI | Logic analyser D1 (and looped to GPIO 13) |
| GPIO 13 | MISO | Logic analyser D2 |
| GPIO 10 | CS   | Logic analyser D3 |
| GND     | GND  | Logic analyser GND |

Settings: 100 kHz, 8-bit, MSB first, Mode 0 (CPOL=0, CPHA=0).
MOSI is looped back to MISO so the received bytes prove the MISO path is really sampled.

### Serial output
```
SPI TRANSMISSION
100 kHz, 8-bit, MSB first, Mode 0
TX DATA: 55 AA 10 25
RX DATA: 55 AA 10 25
SPI: TRANSMISSION COMPLETE
```

### Observation table
| Signal | Observation |
|---|---|
| SCK  | Idles LOW (CPOL=0). 32 pulses per frame (4 bytes x 8 bits) at 100 kHz -> 10 us period. Only toggles while CS is LOW |
| MOSI | Master-out. 0x55 = 01010101 (densest edges), 0xAA = 10101010, 0x10 = 00010000, 0x25 = 00100101. MSB first |
| MISO | Master-in. Mirrors MOSI through the loopback, so RX reads back 55 AA 10 25. With no slave driving it, it would stay idle |
| CS   | Idles HIGH. Driven LOW just before the transfer, released HIGH after - it frames one complete 4-byte transaction |
| Data transmitted | 0x55, 0xAA, 0x10, 0x25 |

### Signal flow
CS LOW selects the slave -> master generates SCK -> on each rising edge (CPHA=0) the slave
samples MOSI while the master simultaneously samples MISO -> after 32 edges CS returns HIGH.
SPI is full-duplex: one byte out and one byte in per 8 clocks.

## Activity 3 - UART Command-Based Control System

### Connections (as specified)
| ESP32-S3 GPIO | UART signal | Goes to |
|---|---|---|
| GPIO 17 | TX (UART1) | Serial terminal RX |
| GPIO 18 | RX (UART1) | Serial terminal TX |
| GPIO 2  | LED output | 220 ohm -> LED anode; LED cathode -> GND |

Settings: 9600 baud, 8 data bits, no parity, 1 stop bit.

### Terminal session
```
ESP32-S3 UART READY
HELP
LED ON / LED OFF / STATUS / HELP
LED ON
LED TURNED ON
STATUS
SYSTEM OPERATIONAL
LED OFF
LED TURNED OFF
STATUS
SYSTEM OPERATIONAL
```

### Command table
| Command | Response |
|---|---|
| LED ON  | LED TURNED ON (LED on GPIO2 lights) |
| LED OFF | LED TURNED OFF |
| STATUS  | SYSTEM OPERATIONAL |
| HELP    | LED ON / LED OFF / STATUS / HELP |
| other   | UNKNOWN COMMAND |

### Observation table
| Parameter | Observation |
|---|---|
| Baud rate | 9600 bit/s -> 104.2 us per bit; one 8-N-1 character = 10 bit times = 1.04 ms |
| TX pin | GPIO 17 - idles HIGH, falls for the start bit, then 8 data bits LSB-first, then a HIGH stop bit |
| RX pin | GPIO 18 - receives typed characters; `uart.any()` reports how many bytes are buffered |
| Command received | LED ON, LED OFF, STATUS, HELP (terminated by CR or LF) |
| Response generated | LED TURNED ON / LED TURNED OFF / SYSTEM OPERATIONAL / command list |
| LED status | ON after LED ON, OFF after LED OFF |

### Signal flow
No shared clock - both ends are pre-agreed on 9600-8-N-1. The receiver detects the HIGH->LOW
start-bit edge, waits half a bit time, then samples every 104.2 us. The firmware buffers bytes
until it sees CR or LF, parses the line, and writes the reply out of TX.

## Final task - Protocol comparison

| Feature | I2C | SPI | UART |
|---|---|---|---|
| Communication type | Synchronous | Synchronous | Asynchronous |
| Clock | SCL (shared, master-driven) | SCK (master-driven) | None - agreed baud rate |
| Data wires | SDA (1, bidirectional, half-duplex) | MOSI + MISO (full-duplex) | TX + RX (full-duplex) |
| Minimum wires | 2 | 4 (3 + 1 CS per slave) | 2 |
| Device selection | 7-bit address on the bus | Dedicated Chip Select per slave | None - point-to-point |
| Speed (as used here) | 100 kHz | 100 kHz (commonly tens of MHz) | 9600 baud |
| Typical use | Sensors, EEPROMs, LCD backpacks | Displays, flash memory, ADCs, SD cards | Debug consoles, GPS, modems, PC links |
| Error checking | ACK/NACK per byte | None built in | Optional parity bit |
| Measured here | 1 device at 0x27 | 32 SCK pulses per 4-byte frame, CS framing | 104.2 us per bit |

**Why the trade-off exists:** I2C spends clock cycles on addressing and ACKs, so it is the
slowest but needs only two wires for many devices. SPI drops addressing and error checking in
exchange for raw speed and full-duplex, at the cost of one extra pin per slave. UART removes
the clock wire entirely, which suits long point-to-point links, but both ends must agree on
timing in advance.

## Note on the simulator

Proteus 8.17 SP2 is installed on this machine but has **no ESP32-S3-DEVKITC-1 model**.
Proteus VSM for MicroPython is a **Proteus 9** feature - 8.17's MicroPython library
(`VSMPY.LIB`) contains only the Raspberry Pi Python Interpreter, and a scan of all 136
device-library index files found no Espressif part. These activities were therefore built in
Wokwi, which provides a real ESP32-S3-DEVKITC-1 running MicroPython with a working I2C LCD,
logic analyser and serial terminal.
